# 정보 및 뉴스 운영

매일 오전 9시(Asia/Seoul) 이 대화의 자동화에서 공식 발표를 확인한다. 신규 노선, 호텔·공항 운영 변경 등 실제 여행 판단에 유용한 소식만 최대 2건 선별한다. 공식 원문 URL·발표일·적용 기간·대상·조건·확인일을 검증하고 한국어·영어로 작성한다. 중요 사실을 추측하지 않으며 원문을 복제하거나 직접 경험한 것처럼 쓰지 않는다.

작업 중 초안 위치: `.blog-editor/news-drafts/YYYY-MM-DD-slug/{ko.md,en.md,sources.json}`. 공개 글 폴더에 넣지 않는다. 기존 초안 및 게시물과 URL·주제로 중복을 확인한다. 이 경로의 초안은 Editor 임시저장 탭과 별개로 Codex 대화에서 검토한다.

2026-09-15 사용자 승인에 따라 검수 완료 후 별도 승인 없이 자동 발행한다. 한국어는 `_posts/news/`, 영어는 `_en_posts/news/`에 저장한다. category: news, hidden: true, sitemap: true와 적절한 한·영 레이아웃, description, 상호 언어 링크를 넣는다. hidden은 페이지네이션 제외용이며 검색 차단 설정이 아니다. `_config.yml`의 폴더 기본값도 이를 보장한다.

카테고리 진입: `/categories/` → `/category/news/`, `/en/categories/` → `/en/news/`. 메인 최신 글·목록·내부 검색에서 제외하되 카테고리와 게시물은 사이트맵에 포함한다. 사진·사실·문체 검수와 빌드 검증을 통과하면 해당 파일만 commit하고 origin main에 push한다. 공개 URL 반영까지 확인해 완료를 알린다. 추가 승인 대기로 멈추지 않는다. 검수에 실패한 글은 초안으로 보관하고 이유를 기록한다.

## 문체

사용자가 쓴 기존 후기 몇 편을 읽고 본문은 짧고 편한 존댓말을 쓴다. 본문에서 반말 종결(한다, 이다, 하자)은 쓰지 않는다. 소제목에는 존댓말을 쓰지 않고 “예약 이관 일정”, “변경 후 확인 사항”처럼 간결한 명사형을 쓴다. 과장된 수식어, 홍보 문장, 상투적인 AI 표현, 이모티콘을 쓰지 않는다. '특별한 경험', '완벽한 선택', '매력적인 여행', '새로운 지평' 같은 빈말 대신 무엇이 바뀌었는지 구체적으로 쓴다. 실제 경험이 없는 뉴스에는 체험담을 만들지 않는다. 한국어와 영어 모두 자연스럽게 쓰되 정확성을 유지한다.

사진은 기사에 나오는 항공사·기종·공항·장소와 직접 관련된 것을 고른다. 공식 보도 사진도 사용 조건을 확인하고, 불가능하면 상업적 이용이 허용된 외부 사진을 사용한다. 촬영자·출처·라이선스 표기를 지킨다. 캡션은 대상·장소와 필요한 출처만 짧게 쓴다. “이 글의 사진은 모두 이전 여행에서 찍은 사진이다” 같은 글 자체에 대한 해설은 넣지 않는다. 다른 장소에서 촬영한 항공기 사진은 실제 촬영 장소를 명시한다.

## 사진·내용 필수 검수

모든 정보·뉴스 글은 본문에 서로 다른 관련 사진을 최소 3장 넣는다. 대표 이미지와 본문에서 같은 사진을 반복한 것은 두 장으로 세지 않는다. 한국어·영어 모두 적용한다. 직전 기사 사진을 편의상 재사용하지 않는다. 항공사·공항·객실·목적지 등 해당 문단과 직접 관련된 사진을 각각 고르고 실제 이미지를 열어 확인한다. 수량을 채우기 위한 무관한 사진, 다른 항공사 사진, 같은 사진의 잘라낸 변형은 금지한다. 관련성과 이용 조건을 충족하는 사진 3장을 확보하지 못하면 발행 준비 완료로 처리하지 않는다. 촬영 시점·장소를 오해하지 않도록 필요한 경우 캡션에 표기하고 출처·촬영자·라이선스를 보관한다.

일정·대상·조건·비교·예약 확인 사항처럼 표로 읽기 쉬운 정보는 표로 정리한다. 기사에는 여행자가 실제로 확인할 항목과 구체적인 영향을 담되 분량을 늘리기 위한 미사여구는 쓰지 않는다. 공식 발표로 확인된 사실, 작성자의 제안, 아직 확인되지 않은 사항을 구분한다. 중요한 수치·날짜·대상·예외를 공식 원문과 대조하고, 공개 전 두 언어의 본문 사진 3장 이상·관련성·표·출처 링크·사실 일치를 검수한다.
